## 可直接复用的换算工具

**冷藏发酵的温度—时长换算（Q10 法）**

```
速率比 = Q10^(ΔT ÷ 10)，Q10 ≈ 2.2（5–30℃ 通行经验值）
等效时长 = 原时长 ÷ 速率比
```

- 简记：**温度每升高 1℃，时长 × 0.92（−8%）**
- 4℃ → 6.5℃：时长 × 0.82（14 h → 11–12 h；12 h → 10 h；10 h → 8 h）
- 边界：**4℃ 已接近酵母低温抑制区，实际加速可能大于 Q10 外推** → 结论报区间不报点值，并提示"从短的一端起试"
- 同一模型可用于：一发温度、冷藏二发、鲁邦种喂养温度的时长互换

## 已排除的诊断方向（不要重复怀疑）

- ❌ 出缸面温偏低（实测 23.8℃ 正常）
- ❌ 鲁邦种活力不足（1:1:1 喂养 2 h 到 2 倍，高活性）
- ❌ 冷藏水合 12 h 削弱面筋（是冷藏 4℃ 做的，酶活性极低）
- ❌ 蒸汽 5 秒不足（Hamelman 标准就是总注入 4–6 秒，5 秒正确）
- ❌ 切太早导致压塌（出炉 6 h 才切）

## 仍未定位

- **一发 5 h / 24℃ 只到 +25%（小样瓶）的原因**。当前候选：① 小样瓶读数可靠性（同时给 1.25× 和 1.5×，差 20 个点）② 折叠节奏干扰读数（末次折叠距整形仅 1 h）③ 种与面团混匀不足 ④ 接种量 18.2% 偏低 ⑤ 69% 低水合体积响应保守

## 用户的实际制作流程（10-03 用户确认）

| 阶段 | 做法 |
|---|---|
| 鲁邦种 | **3 年老种**，用**野性 T65** 养，1:1:1 喂养 |
| 一发 | **常温约 5 小时** |
| 整形 | 一发结束后整形 |
| 二发 | **整形后冷藏 14 小时** |
| 烘烤 | 冷藏二发结束直接烤 |

**⚠️ 关键：用户的冷藏阶段在二发（整形之后），不是一发。**

讨论「低温发酵」时必须区分这两种，作用完全不同：
- 低温**一发**（bulk retard，整形前）→ 面团继续整体发育、风味发展
- 低温**二发**（final proof retard，整形后）→ 缓慢充气 + 定型（变硬、好割包）

**我 10-03 曾用「峰值前取用可支撑漫长的低温一发」作为理由推荐年轻种 —— 对该用户不成立，已更正。** 「种里剩余食物」这条论据的作用点应是用户的**常温 5h 一发**，且方向取决于一发是欠发还是过发。

**推论：用户流程中「一发结束时的发酵程度」是决定入炉膨胀与耳朵的首要变量，而非种是否在峰值。**

## 我犯过的第三类错误（10-04 新增，作答前自查）

**记录敏感信息时把敏感串原样复述。** 清理公开仓库里的微信 ID 时，我在同一次操作里把该 ID、两个旧提交 SHA、Token 前缀又写进了要公开的记忆文件——等于一边清理一边重新公布。清理脚本本身也是泄露源（待查字符串写成字面量并存盘）。

**做法：清理记录一律只描述、不复现。** 需要引用的标识符用 `xxx_***` / `[旧提交]` 之类占位符；扫描脚本用拼接构造字符串或 heredoc 内联执行，不落盘。

**配套的技术事实：`git push --force` 不清除内容。** 被强推掉的提交在 GitHub 上仍可通过完整 SHA 直连访问（raw / API 均返回 200），实测验证过。要真正清除只能删库重建或找 GitHub 支持 GC。详细流程见 skill `github-push-sanitize`。
