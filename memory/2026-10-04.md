### 换算过程（本题核心）

- 模型：Q10 温度系数，Q10 ≈ 2.2（5–30℃ 通行经验值）
- `速率比 = Q10^(ΔT÷10) = 2.2^(2.5÷10) = 2.2^0.25 ≈ 1.22`
- `等效时长 = 14 h ÷ 1.22 ≈ 11.5 h`
- 敏感性：Q10 = 2.0 → 1.19×（11.8 h）；Q10 = 2.5 → 1.26×（11.1 h）
- **好记的规则：温度每升高 1℃，时长 × 0.92（减约 8%）**
- 对照表：4℃ 10 h → 6.5℃ 约 8 h；12 h → 约 10 h；**14 h → 11–12 h**

### 结论与关键限定

- **建议 6.5℃ 做 11 h（区间 10–12 h），从 11 h 起试、10 h 时先看一次状态**

### 关键机制认知（以后务必记住）

1. **`git push --force` 不清除内容。** 被强推掉的提交在 GitHub 上**仍可通过完整 SHA 直连访问**（实测 API `/commits/<old_sha>` 与 `raw.githubusercontent.com/<repo>/<old_sha>/<path>` 均返回 HTTP 200，且内容含敏感串）。远端正式 GC 不可达对象的时间**不确定**（数周级）。
2. **加新提交删掉内容 = 完全无效**，旧 blob 仍在历史里可达。
3. **要真正清除，只有三条路**：① 删库重建（最彻底）② 联系 GitHub Support 请求 GC ③ 等自然回收。
4. **清除后不要再公开旧 SHA**，否则等于没清。
5. 本地想让旧对象立刻失效，需 `git update-ref -d refs/remotes/origin/main` + 删 `.git/ORIG_HEAD` + `git reflog expire --expire=now --all` + `git gc --prune=now`。**只做后两步不够**——`origin/main` 跟踪引用会拖住旧对象（实测：先 gc 后 `git cat-file -e` 仍返回存在，删掉跟踪引用后才消失）。
